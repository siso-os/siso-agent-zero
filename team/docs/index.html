The three roles — front doors, not personas

BRAIN

project-agent-zero

Reads, in order: team.yaml → charter + state → intent, newest first → last three handoffs → Plane → the project's estate skill. Turns every sentence of Shaan's into a work item and a brief. One owner per domain; closes the pane when the handoff lands. Never dispatches arms. Never polls. Speaks to Shaan through the console and one page with a visual. Writes the digest for tier 0. Runs intent-capture and publish-front at close-out.

OWNERS

owner

Loads siso-owner for how to think, this for how the team runs. Boots on the brief, the intent file, the estate skill — nothing else. 20–60k tokens; past 150k, hand off and exit. Done means seen in a browser through the team's browse tool. Mechanical work goes to an arm with a full brief; no arms → inline or built-in sub-agents, said out loud. Shared index: commit -- paths only. One az-send report, then exit.

ARMS

worker-contract

No judgement, no rediscovery, no scope. The JOB brief has OWNER PANE · INPUT · DO · DO NOT · OUTPUT · CHECK · RETURN · STOP; if any line is missing the owner has not finished thinking. Work inside FILES, run CHECK, return a path and a window, send the one message, stop. Qwen for convert/grep/draft/bulk with everything inline; Luna for a bounded implementation that needs a real repo read.

Three roles is the cap. The Oracle diet (below) measured well-run agent repos at ~0 personas and ≤3 as the ceiling; the tool skills each role carries are the existing SISO ones, not new ones.

DON'T BUILD

  • A new tracker. Plane stays the board. Beads is decided after a week of ephemeral owners, beside Plane if at all.
  • Another Agent Zero protocol repo, or one per project. Tier 0 stays where it is; project Agent Zeros live in companions. (Supersedes the 2026-09-10 "no per-project Agent Zero" note only in that a per-project Agent Zero now exists — still one package repo.)
  • A model gateway or proxy. Ruled out 2026-09-09; each harness talks to its own provider.
  • Anything on a schedule. Ruled out 2026-09-04. Intent capture and publishing are close-out steps, not cron.
  • Per-owner bespoke skills. One owner skill plus the team's domains table. A domain that repeats across three teams earns a tool skill, not a persona.
  • Full adoption of siso-project-os. Its packets, lanes and claims are heavier than a team needs; its idea of a project spine survives as team.yaml.
  • A reviewer role for ordinary diffs. Oracle's "parent acceptance" cost days and landed nothing; the only cold review is of sensitive paths, answering SHIP / FIX-FIRST / RETHINK (evidence).
  • Per-unit receipts, ACK files, evidence folders. Oracle grew 3,000+ dated files and its agents stopped reading any of them; one ledger per kind in the companion (evidence).
  • Hand-built front ends per team. The next step is tools/render-front reading team.yaml; this page is written by hand exactly once.

ONLY SHAAN open decisions carried from the 11:18Z draft

  • Double the Labs host's RAM to 16 GB (~$10/month): nine resident CLIs plus OpenWA do not fit in 7.9 GB and produced three OOM kills. Ephemeral owners shrink this; the box is still tight.

  • The compute-pool loop timer was disabled at 23:43Z on 10 Sep by someone — deliberate or not decides whether Qwen arms exist.
  • Which Codex account the arms run on, and the Codex login on the VPS (build item 3).
  • The compute-pool box escalated a gate-test contract question to a human (its STATE.md, 2026-09-11 tail): a test encodes the old blanket-deny rule for tools/test_*.py; main there is red until someone says which contract is intended.
